# Rule Mapping Reference

Per `architecture.md` §1 (document-as-ground-truth convention): every
rule-check function in the engine cites which source document and section it
implements. This file is that cross-reference, kept up to date as each
module is built from Phase 2 onward.

Source documents are referenced by number and short name, matching
`phase0-knowledge-extraction.md` §1 (e.g. "doc 06/16/20" for the confirmed
single-source cluster, "doc 02" for `02-unified-logic-market-structure.md`).

Add one row per rule-check function as it's written. If a function
implements a judgment call rather than a directly-sourced rule (see Phase 0
§7), say so explicitly in the "Source" column instead of citing a document —
never attribute an invented rule to the material.

| Function | Document / Section | Plain-English rule | Notes |
|---|---|---|---|
| `SNRZoneModule._detect_zones` (zone formation) | Docs 09 p.9-11, 16 p.9, 20 p.9 ("GAP (Open-Close) SNR"); corroborated generically across docs 04-07, 10, 12, 15, 18 ("ignore the wicks" rule) | A support/resistance zone forms in the gap between one closed candle's body close and the next candle's body open. Wicks are ignored. | Phase0 §2.3. |
| `SNRZoneModule._detect_zones` (fresh → unfresh) | Doc 20 §14 (Fresh/Unfresh lifecycle) | A zone starts "fresh"; the first bar whose wick range touches the zone without fully closing through it flips the zone to "unfresh." | Phase0 §2.3. |
| `SNRZoneModule._detect_zones` (flip / RBS-SBR) | Doc 20 §15; universal RBS/SBR mechanic (docs 04-07, 10, 12, 13, 15, 16, 18, 20) | A bar whose *close* fully breaks through the zone flips its role (support↔resistance) and resets it to fresh in the new role. | Phase0 §2.3. |
| `SNRZoneModule.evaluate` (bias direction) | Doc 06/16/20 "A"-shape resistance rejection / "V"-shape support rejection (candle-close-based, not wick-based) | A bullish-bodied bar closing back above a support zone's bottom = bullish rejection; a bearish-bodied bar closing back below a resistance zone's top = bearish rejection. | Phase0 §2.3, §4. |
| `SNRZoneModule.__init__` (`min_gap_ratio` threshold) | Not source-stated — Phase0 §7 item pattern (judgment call, documented not invented) | A close→open gap must be ≥ a fraction of the instrument's average bar range to count as a zone. | Added after live validation showed the raw "any gap" rule producing sub-cent noise zones on Binance BTCUSDT 1h data. Default (0.08) calibrated off the EUR/USD gap-size distribution, where the concept is actually applicable — see `snr_zone.py` docstring. On continuous markets (Binance-style crypto) this module correctly detects few/no zones; that's expected, not a bug — see next row. |
| `SNRZoneModule` scope limitation (continuous markets) | Not source-stated — empirical finding from Phase 2 validation | This module's zone concept doesn't transfer to 24/7 continuous markets (crypto): live-data testing showed BTCUSDT close→open gaps sitting at 0.01–0.07% of average bar range even at the 99th percentile, vs. EUR/USD's real distribution (~9% at the 90th percentile, concentrated at the 21:00 UTC forex session rollover). | A different, swing-based zone-formation rule would be needed for crypto; deliberately not force-fit into this module. Candidate follow-up module. |
| Swing-high/low ("Classic V/A") zones | Not implemented | — | Deliberately deferred: the source material never gives a swing-formation rule (doc 08 itself notes swing highs/lows are diagrammed but never formally defined). Implementing one would mean inventing an un-sourced convention. Candidate follow-up module, flagged not silently added. |
| `MarketStructureModule._structure_events` (BOS = continuation, CHoCH = reversal) | Doc 06 p.8, corroborated corpus-wide | A close that breaks a swing level in the direction of the current trend is a BOS (continuation); a close that breaks a swing level against the current trend is a CHoCH (reversal). | Phase0 §2.1. |
| `MarketStructureModule._structure_events` (break validity) | Doc 20 §§36-37 | A structure break requires the bar's *close* to fully clear the swing level — a wick beyond it doesn't count. | Phase0 §2.1, §7 item 3. |
| `MarketStructureModule` (MSS = CHoCH) | Phase0 §7 item 3 (judgment call, not source-stated as a single answer) | MSS is treated as a synonym for CHoCH, not a third distinct signal. | Doc 12 draws a three-way BOS/CHoCH/MSS distinction; most other documents use CHoCH and MSS interchangeably. Resolved by explicit decision, documented as such — see Phase0 §7. |
| `MarketStructureModule._find_swings` (`swing_strength` fractal rule) | Not source-stated | A bar is a swing high/low if it's strictly the most extreme high/low within `swing_strength` bars on each side (standard fractal/pivot convention; default 2 = "5-bar fractal"). | Added because BOS/CHoCH is used universally in the corpus but no document gives a swing-formation rule (doc 08 notes this gap explicitly). External, standard TA convention, not invented for this project specifically — documented per the project's rule. Validated live on both Binance BTCUSDT and Twelve Data EUR/USD across 1h/4h/1d without needing the kind of materiality-filter correction the SNR Zone module required — this concept doesn't have the same continuous-market blind spot. Extracted into the shared `analysis/swings.py` utility so `LiquiditySweepModule` reuses the same code (shared math, not module cross-talk). |
| `LiquiditySweepModule` (BSL/SSL definition) | Doc 08 §53 | BSL = liquidity above swing highs where retail sell-stops rest; SSL = liquidity below swing lows where retail buy-stops rest. | Phase0 §2.2 — the single most-corroborated mechanic in the whole corpus, though naming varies wildly (inducement/IDM/"Trap"/"TS" across different documents). |
| `LiquiditySweepModule._levels_and_sweeps` (sweep = wick-through + close-back) | Universal corpus mechanic ("stops get run before the real move"); distinguished from a genuine break via doc 20's full-body-close BOS/CHoCH test (used as the negative case here) | A level is swept when a bar's wick clears it but the bar's body closes back on the origin side — if the close also clears it, that's a structure break (market_structure.py), not a sweep. | Phase0 §2.2. |
| `LiquiditySweepModule.__init__` (`swing_strength=5` default, distinct from `MarketStructureModule`'s 2) | Not source-stated | Liquidity levels use a coarser swing-detection window than structure breaks. | Added after live validation: at strength=2, 15.4% of BTCUSDT 1h bars registered a sweep (~1 every 6 bars) — reads as routine noise, not the decisive event the corpus describes. The swept/level ratio (~70-75%) stayed constant across every strength tested, confirming this is a granularity choice, not a detection bug. The corpus names both minor (any swing) and major (PWH/PWL/PDH/PDL, EQH/EQL) liquidity without a formula distinguishing them — `swing_strength` is this module's stand-in lever until EQH/EQL clustering exists. |
| EQH/EQL clustering | Not implemented | — | Deferred, same reasoning pattern as SNR Zone's deferred Classic V/A: would need its own un-sourced "how close counts as equal" tolerance. Candidate follow-up, flagged not silently added. |
